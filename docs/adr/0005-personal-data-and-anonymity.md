# ADR-0005. Персональные данные, отмена анонимности и права субъекта

**Статус:** Принято
**Дата:** 2026-10-27
**Связано:** ТЗ п. 4.1.5, 4.8, 6.5, 7.2.7, 7.5.2, 8.2–8.4, 9.1.7, 9.2, 9.3.1; CLAUDE.md «Персональные данные и безопасность», «AI-сводка»; backlog F-003, F-006, F-033, F-047, F-049, F-059, F-062, G-04, G-05, G-06, G-11, G-12, G-26, Q-10, Q-11, Q-15, Q-21, Q-22, Q-31; решения заказчика В-04, В-05, В-06, В-11, В-14, В-15, В-17, В-19 и отмена анонимности (2026-10-27); вопросы юристу — `docs/legal-questions.md`

## Контекст

Система обрабатывает ПДн и самооценку состояния сотрудников (152-ФЗ, серверы в РФ). В backlog были открыты два противоречия:
- **G-04** — анонимный комментарий технически можно было связать с автором.
- **G-11** — не была определена судьба сводок, журнала и данных удалённого проекта.

Решения заказчика от 2026-10-27:
1. **Анонимных ответов и комментариев нет.** Все ответы и комментарии привязаны к участнику.
2. **Удаление аккаунта, проекта и ответов исключённого участника — физическое и сразу** (В-05, В-15).
3. **Записи журнала, связанные с удалённым пользователем или проектом, удаляются целиком** (В-19).
4. AI-сводки хранятся с псевдонимами. Запись словаря удаляется при любом исключении участника и при удалении аккаунта (В-04, В-17).
5. После удаления аккаунта остаётся минимальная запись о согласии (В-11, вопрос юристу ЮВ-2).

## Решение

### 1. Отмена анонимности: G-04 и Q-15 закрыты

- Галочки «Отправить анонимно», отдельного эндпоинта, отдельной таблицы, порога «меньше 3» и лимитов нет. Комментарий (до 1000 символов) — поле подписанного ответа, его можно изменить до закрытия дня.
- **G-04, G-05, G-06, G-26 и Q-15 закрыты отменой анонимности.**
- **Сознательное отступление от ТЗ по решению заказчика.** В реализации не действуют:

  | Пункт ТЗ | Что говорит ТЗ | Как в реализации |
  | --- | --- | --- |
  | п. 6.5.2–6.5.5 | Галочка анонимности, отдельная таблица, неизменяемость, порог 3 | Нет |
  | п. 4.8.2 | Анонимные комментарии исключённого участника не удаляются | Неприменимо |
  | п. 7.2.7 | Анонимные комментарии помечены в ленте | У всех комментариев указан автор |
  | п. 7.5.2 | В CSV пометка «анонимно» | Всегда указан автор |
  | п. 8.2.1 | Комментарии уходят в нейросеть с пометкой «анонимно» | Уходят с псевдонимом автора (R2) |
  | п. 9.2.4 | Анонимные комментарии остаются после удаления аккаунта | Все комментарии удаляются вместе с ответами |

- Продуктовый риск — ADR-0008, Р-1.

### 2. Где лежат ПДн (реестр)

| Данные | Где | Срок |
| --- | --- | --- |
| Email, имя, язык | `users` | До удаления аккаунта |
| Email до регистрации, коды | `login_codes` (HMAC) | Просроченные чистятся ежечасно |
| Устройства | `personal_access_tokens` (SHA-256) | До отзыва или удаления аккаунта |
| Сессии | Redis (без IP и user-agent) | 14 дней; при удалении аккаунта удаляются сразу |
| Факт согласия | `user_consents`: дата, версия, ID, без ПДн | Остаётся после удаления аккаунта (ЮВ-2) |
| Членство, роли, заявки | `memberships`, `join_requests` | До удаления аккаунта или проекта |
| Ответы и комментарии | `responses`, `response_answers` | До удаления аккаунта, исключения с удалением ответов или удаления проекта |
| Агрегаты по участнику | `daily_member_stats` | Удаляются вместе с ответами |
| Журнал действий | `audit_log` (только идентификаторы) | 1 год; записи удалённого пользователя или проекта удаляются сразу (В-19) |
| Файлы экспорта | `storage/app/exports` | 24 часа; при удалении аккаунта или проекта — сразу |
| Словарь псевдонимов (R2) | `ai_summary_pseudonyms` | До исключения участника или удаления аккаунта |
| Логи Nginx | файлы в томе | Не более 30 дней |
| Логи приложения | stderr / файл | Без тел запросов и IP |
| Резервные копии | при выборе хостинга | 14 дней (ЮВ-3) |

### 3. Согласие на ПДн (В-06, В-11)

- Тексты лежат в БД (`consent_documents`) и публикуются artisan-командой без релиза.
- Согласие — отдельный экран и отдельная галочка, запись `user_consents` без IP.
- Пока текущая версия не принята, API отвечает `consent_required` и **отклоняет приём ответов** (ADR-0003).
- После удаления аккаунта остаётся запись «ID, версия, дата». **Вопрос юристу ЮВ-2.**

### 4. Удаление и G-11 (В-04, В-05, В-15, В-17, В-19) — закрыт

Принципы:
- Хранить идентификаторы, имена подставлять при показе.
- Удаление ПДн — физическое, сразу и в одной транзакции через реестр модулей (ADR-0001, ADR-0004).

| Ситуация | Ответы, комментарии, агрегаты | Журнал действий | AI-сводки (R2) | Учётные данные, экспорты |
| --- | --- | --- | --- | --- |
| Удаление аккаунта (п. 9.2.4) | Удаляются во всех проектах | Удаляются все записи, где пользователь — автор или объект | Записи словаря удаляются | Токены, сессии, коды, файлы экспорта его проектов удаляются |
| Исключение «оставить ответы» (п. 4.8) | Остаются как «Бывший участник» | Без изменений | Запись словаря удаляется (В-17) | — |
| Исключение «удалить ответы» | Удаляются сразу (В-15) | Без изменений | Запись словаря удаляется | Файлы экспорта проекта удаляются |
| Удаление проекта | Удаляется всё | Удаляются все записи проекта | Удаляются | Файлы экспорта и коды удаляются |

- **Журнал (В-19).** После удаления пользователя или проекта в журнале не остаётся записей с его ID. Цена этого: пропадает и запись о самом удалении проекта, и история действий удалённого администратора в проектах, которые продолжают работать. Это расходится с назначением журнала по ТЗ п. 9.1.7 (ADR-0008, Р-23).
- **AI-сводки (R2).** Хранятся текст с псевдонимами и словарь `псевдоним → membership_id`. Имена подставляются только при показе. **Если запись словаря удалена, в старой сводке псевдоним показывается как есть («Участник 3»), без имени.**

### 5. Выгрузка «мои данные» и профиль (В-14)

- Общая страница профиля доступна любому аккаунту: устройства, выгрузка данных, удаление аккаунта.
- Выгрузка — JSON-архив из `PersonalDataLifecycle::export`, собирается в очереди `default`, ссылка действует 24 часа. Формат — Q-31.
- Удаление аккаунта владельцем проекта — Q-22. По умолчанию запрещено, пока он не передал владение.

### 6. Прочее

- IP с ответами не хранится, для rate limiting он используется только в памяти.
- Логи и мониторинг не пишут тела запросов.
- Медицинские термины не используются (G-20).
- Администратор одного проекта не видит данные другого. Это проверяется тестом на каждый эндпоинт.

## Рассмотренные альтернативы

1. **Анонимные комментарии с защитой от деанонимизации.** Отменены заказчиком.
2. **Мягкое удаление с ручной очисткой.** Отменено заказчиком.
3. **Журнал с обнулёнными ID вместо удаления записей.** Отклонено заказчиком (В-19).
4. **Снимок имён в сводках и журнале.** Нарушает право на удаление. Отклонено.

## Последствия

- (+) Схема и код проще.
- (+) Удаление по запросу выполняется сразу и полностью, ПДн субъекта не остаются ни в данных, ни в журнале.
- (−) Отступление от ТЗ п. 6.5 и связанных пунктов (Р-1).
- (−) Удаление необратимо (Р-17).
- (−) Журнал теряет часть истории при удалениях (Р-23).
- (−) Удалённые данные остаются в резервных копиях до 14 дней (ЮВ-3).
