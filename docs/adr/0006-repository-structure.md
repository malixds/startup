# ADR-0006. Структура репозитория: монорепозиторий

**Статус:** Принято
**Дата:** 2026-10-27
**Связано:** ТЗ п. 3.4.2, 9.4, 11; CLAUDE.md «Структура репозитория», «Как работать», правило 8; backlog F-067, F-070, F-073; решение заказчика В-12

## Контекст

- Три клиента одного API: кабинет, `/survey` и расширение. Форма опроса одна для трёх мест.
- Изменение API и OpenAPI делается в одном коммите (CLAUDE.md). CI блокирует слияние при красном статусе.
- Заказчик получает один репозиторий с полной историей (п. 11.1). Репозиторий — GitHub (`origin`).
- CLAUDE.md уже предлагает `backend/`, `extension/`, `docs/`.

## Решение

**Монорепозиторий** с npm workspaces для JS-части:

```
/
  backend/                 # Laravel (кабинет, /survey, профиль, API, воркеры)
    app/Modules/<Module>/  # ADR-0001
    app/Shared/
    resources/js/          # Inertia + Vue: кабинет, /survey, профиль
    resources/prompts/     # промпты (R2)
    lang/{ru,en}/          # ошибки API, письма
  extension/               # WXT (ADR-0003)
  packages/
    survey-ui/             # общая форма опроса (Vue), типы API, строки формы ru/en
  docker/                  # Dockerfile PHP, конфиги nginx, php.ini, postgres
  compose.yaml             # локальная разработка (ADR-0007)
  docs/
    adr/                   # этот каталог
    product/               # backlog
    openapi/openapi.yaml   # спецификация /api/v1
    er.md                  # ER-диаграмма (mermaid, из ADR-0004)
    new_types.md           # реестр новых типов сущностей (правило 8 CLAUDE.md, В-12)
    legal-questions.md     # вопросы юристу
  .github/workflows/       # CI
  package.json             # npm workspaces: backend, extension, packages/*
  .env.example             # общий шаблон для compose
```

- `packages/survey-ui` подключается как исходники, без собственного шага сборки: Vite в `backend` и WXT в `extension` компилируют его сами. Внутри — компонент формы, компоненты типов вопросов, валидация обязательных полей, TS-типы контракта API и JSON-строки ru/en.
- Типы контракта на старте пишутся вручную рядом с OpenAPI. Если ручные типы начнут расходиться со спецификацией, можно подключить генерацию (`openapi-typescript`, dev-зависимость).
- CI на GitHub Actions состоит из отдельных задач с фильтром по путям:
  - backend — Pint, Larastan, тесты, `composer audit`;
  - frontend и `packages` — ESLint, Prettier, type-check, `npm audit`;
  - extension — lint и build для всех целей текущего релиза.

  Слияние в `main` возможно только при зелёном CI.
- ТЗ остаётся в `.claude/TZ/` и в `docs/` не переносится (Q-33).
- `docs/new_types.md` создаётся с первым PR реализации (В-12).

## Рассмотренные альтернативы

1. **Отдельные репозитории для backend и extension.** Релизы независимы, но изменение API и клиента расходится по двум PR, а общий пакет формы пришлось бы публиковать в registry. Отклонено.
2. **Монорепо без workspaces, общий код копируется.** Настройка проще, но форма начнёт расходиться между `/survey` и расширением. Отклонено.
3. **Nx / Turborepo.** Кэш и граф задач не нужны для двух JS-проектов. Отклонено как лишняя зависимость.

## Последствия

- (+) API, OpenAPI, клиенты и ADR меняются атомарно, в одном PR.
- (+) Одна форма и одни типы для расширения, `/survey` и предпросмотра.
- (−) `packages/survey-ui` не должен зависеть от Inertia и `browser.*` — только от Vue, пропсов и событий. За этим нужно следить.
- (−) Один `node_modules` на корень: обновление Vue затрагивает кабинет и расширение одновременно. Скорее плюс, чем минус.
