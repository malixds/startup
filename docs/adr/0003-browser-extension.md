# ADR-0003. Браузерное расширение, API каналов ответа и аутентификация устройств

**Статус:** Принято
**Дата:** 2026-10-27
**Связано:** ТЗ п. 3.3, 3.4, 4.1, 4.3–4.7, 6.1–6.4, 6.7; CLAUDE.md «Расширение», «Персональные данные»; backlog F-001, F-004, F-005, F-010, F-031–F-039, F-078, F-079, Q-09, Q-10, Q-11, Q-32; решения заказчика В-06, В-07, В-08, В-09, В-14

## Контекст

- R1: Chrome, Яндекс Браузер, Edge. R2: Firefox. R3: Safari. Один код (п. 3.1), Manifest V3, TypeScript.
- Разрешения: только `storage`, `alarms` и домен API. Ни вкладок, ни истории, ни контент-скриптов.
- Бейдж показывает число проектов с непройденным опросом. Проверка — при старте браузера, открытии расширения, раз в 60 минут и после отправки. Системных уведомлений нет.
- Форма опроса одинакова в расширении, на `/survey` и в «Предпросмотре» кабинета (F-025, F-037, F-038).
- Вход только по коду из письма. Токен устройства действует бессрочно до отзыва, в БД хранится только его хэш.
- Установка у клиента (on-premise) в R1 не входит (В-07).

## Решение

### Фреймворк и структура

**WXT + Vue 3 + TypeScript.** WXT собирает из одного кода MV3 для Chromium, Firefox и Safari, даёт единое пространство `browser.*` и генерирует манифест под каждый браузер.

```
extension/
  wxt.config.ts            # манифест: permissions, host_permissions из env
  entrypoints/
    popup/                 # Vue-приложение (окно до 400×600)
    background.ts          # service worker: alarms, бейдж, проверка статуса
  src/
    api/                   # клиент /api/v1 (fetch, Bearer-токен, Accept-Language, ретраи); единственное место с базовым URL
    platform/              # тонкая обёртка над browser.*: badge, storage, alarms
    screens/               # экраны п. 6.3 + экран согласия
    stores/                # состояние (проекты, сессия, черновики)
  public/_locales/{ru,en}/messages.json   # имя и описание для магазинов
```

Общая форма опроса, типы контракта API и строки формы лежат в пакете `packages/survey-ui` (ADR-0006). Его используют расширение, `/survey` и предпросмотр.

### Сборки по браузерам

| Браузер | Команда | Артефакт | Релиз |
| --- | --- | --- | --- |
| Chrome | `wxt build -b chrome` | zip для Chrome Web Store | R1 |
| Яндекс Браузер | та же сборка Chrome | Устанавливается из Chrome Web Store (В-08, ТЗ п. 6.1). В каталоге Яндекса не публикуем | R1 |
| Edge | `wxt build -b edge` | zip для Edge Add-ons (по содержимому совпадает с Chrome) | R1 |
| Firefox | `wxt build -b firefox --mv3` | xpi/zip для AMO, `browser_specific_settings.gecko.id` | R2 |
| Safari | `wxt build -b safari` → `safari-web-extension-converter` → Xcode | App Store | R3 |

Правила, которые делают R2 и R3 дешёвыми:
1. Код фич не обращается к `chrome.*` напрямую — только через `browser.*` из WXT и `src/platform/`.
2. Используем только API, одинаково доступные во всех пяти браузерах: `storage.local`, `alarms`, `action.setBadgeText/BackgroundColor`, `runtime.onStartup/onInstalled/onMessage`.
3. Service worker не держит состояние в памяти: всё, что нужно между пробуждениями, лежит в `storage.local`. Поэтому другая модель фона в Firefox и Safari (event page) ничего не ломает.
4. Особенности, известные заранее: в Firefox MV3 `host_permissions` пользователь выдаёт явно, поэтому в R2 нужен экран запроса разрешения на домен API. Safari требует упаковки в приложение-контейнер и подписи через аккаунт Apple Developer заказчика (Q-09).

### Разрешения и домен API

- `permissions: ["storage", "alarms"]`, `host_permissions: ["https://<API_HOST>/*"]`, где `API_HOST` берётся из переменной окружения сборки (`WXT_API_BASE_URL`). Домен пока — заглушка (Q-09).
- Не запрашиваем `tabs`, `activeTab`, `notifications`, `scripting`, контент-скрипты и `storage.sync` (чтобы токен не уезжал на другие устройства).
- **R1:** один домен API, заданный при сборке. On-premise в R1 не входит (В-07).
- **После R1 (установка у клиента):** в настройках расширения появится поле «адрес сервера», а доступ к введённому домену будет запрашиваться через `optional_host_permissions`. Подготовка уже в R1: базовый URL читается в одном месте (`src/api`).

### Аутентификация

| Канал | Механизм | Хранение и сроки |
| --- | --- | --- |
| Расширение (в будущем и мобильные приложения) | Токен Sanctum (`Authorization: Bearer`) | В БД `personal_access_tokens.token` хранится как SHA-256, в браузере — в `storage.local`. Бессрочный до отзыва (В-09) |
| `/survey`, кабинет, профиль | Cookie-сессия Sanctum (stateful, тот же домен), CSRF | Сессия в Redis: выход после 24 ч бездействия, абсолютный срок 14 дней, оба значения в env (В-09) |

- Токен выдаётся на аккаунт и устройство. В `name` клиент передаёт «браузер, ОС», отдельно хранится тип клиента (`extension`, позже `mobile`, `telegram`): по нему HTTP-слой ставит `channel` (ADR-0001). `last_used_at` обновляется с ограничением частоты.
- Выход в расширении удаляет текущий токен. Устройства отзываются на **общей странице профиля**. Она доступна любому аккаунту, включая сотрудника без доступа к кабинету (В-14); ссылки на неё есть в `/survey` и в настройках расширения.
- Исключение из проекта токен не трогает: доступ к проекту проверяет Policy по `memberships` на каждом запросе (п. 4.5.4).
- Коды входа — 6 цифр, хранятся как HMAC-SHA256 с ключом из env (обычный SHA-256 от 6 цифр перебирается мгновенно). Срок 10 минут, 5 попыток, повторная отправка не чаще раза в 60 с, не больше 10 писем в час на email. Счётчики хранятся в БД и в Redis (RateLimiter). Тот же механизм с назначением `delete_project` подтверждает удаление проекта (В-09).
- **Согласие на ПДн (В-06 — решено).** Пока не принята текущая версия, middleware возвращает `consent_required` на все аутентифицированные эндпоинты. Исключения: профиль, согласие, выгрузка, удаление аккаунта, выход и `GET /me/survey-status`. **Приём ответов и анонимных комментариев при этом отклоняется.** `survey-status` возвращает признак `consent_required`, чтобы расширение показало экран согласия, а не пустой бейдж.

### API каналов ответа (`/api/v1`, единый для расширения, `/survey` и будущего бота)

Ниже эскиз; финальные пути фиксируются в OpenAPI (`docs/openapi/openapi.yaml`).

| Метод и путь | Назначение | Аутентификация |
| --- | --- | --- |
| `POST /auth/codes` | Отправить код на email | нет, rate limit |
| `POST /auth/tokens` | Код → токен устройства (расширение) | нет, rate limit |
| `POST /auth/session` | Код → cookie-сессия (`/survey`) | нет, CSRF |
| `DELETE /auth/tokens/current`, `DELETE /auth/session` | Выход | да |
| `GET /me`, `PATCH /me` | Профиль: имя, язык, флаги `needs_profile`, `needs_consent` | да |
| `GET /consents/current`, `POST /me/consents` | Текст текущей версии и принятие | да |
| `GET /me/devices`, `DELETE /me/devices/{id}` | Устройства | да |
| `POST /invites/resolve` | Код приглашения → название проекта | нет, 10/мин с IP |
| `POST /join-requests`, `GET /me/join-requests` | Подать заявку, статусы | да + согласие |
| `GET /me/survey-status` | Для бейджа и списка проектов: по каждому проекту — рабочий ли день, локальная дата, пройден ли опрос; общий флаг `consent_required` | да |
| `GET /projects/{project}/survey-days/today` | Опрос дня: вопросы с полным описанием, мой ответ (если есть), доступность анонимности с причиной | да, участник + согласие |
| `PUT /projects/{project}/survey-days/today/response` | Создать или заменить ответ (идемпотентно, хранится последняя версия) | да, участник + согласие |
| `POST /projects/{project}/survey-days/today/anonymous-comments` | Анонимный комментарий — **отдельный эндпоинт**, не более одного на участника в день (ADR-0005) | да, участник + согласие |

Выгрузка «мои данные» и удаление аккаунта — действия страницы профиля (Inertia, ADR-0001), а не `/api/v1`.

Общие правила: JSON, локализация по `Accept-Language`, единый формат ошибок `{"error": {"code", "message", "fields"}}`, rate limiting на вход, коды, приглашения и опрос. Ответ «опроса дня» самодостаточен для отрисовки в любом клиенте: тип, настройки, варианты, тексты ru/en, подсказки, обязательность.

### Бейдж и надёжность формы

- Background проверяет статус при `runtime.onStartup`, `onInstalled`, по `alarms.create('status', {periodInMinutes: 60})` и по сообщению от popup после отправки. Проверка — `GET /me/survey-status`, затем `setBadgeText(n > 0 ? String(n) : '')`. В нерабочие дни сервер возвращает «нерабочий», и бейдж пустой.
- Черновик хранится в `storage.local` под ключом `draft:<projectId>:<localDate>`; удаляется после успешной отправки или смены даты. При ошибке сети — сообщение и кнопка «Повторить»; `PUT` идемпотентен, поэтому повтор безопасен. Ответ `consent_required` черновик не стирает.
- Язык берётся из `GET /me`, до входа — из `browser.i18n.getUILanguage()` (ru, иначе en).

### CORS

В Chromium popup расширения с `host_permissions` обращается к API без CORS-проверок. Для Firefox, Safari и как дополнительная защита — allowlist происхождений расширений в `CORS_ALLOWED_ORIGINS` (env). Cookie расширение не использует, поэтому CSRF к нему не относится.

## Рассмотренные альтернативы

1. **Plasmo** — тоже кроссбраузерный, но завязан на React и медленнее развивается, а у нас Vue. Отклонено.
2. **Чистый Vite + webextension-polyfill + свои манифесты.** Меньше «магии», но ручная сборка манифестов под 4 цели и HMR — ровно то, что WXT уже делает. Отклонено.
3. **Ванильный TS без Vue в popup.** Бандл меньше, но форма опроса не переиспользуется в `/survey` и предпросмотре. Отклонено.
4. **Cookie-сессия и для расширения.** Сторонние cookie в расширениях ненадёжны (Safari, Firefox), а ТЗ требует токены устройств. Отклонено.
5. **Анонимный комментарий в теле общего `PUT response`.** Проще для клиента, но тело попадёт в общие логи и в одну транзакцию с подписанным ответом (G-04). Отклонено.
6. **Поле «адрес сервера» уже в R1.** Отложено заказчиком (В-07).

## Последствия

- (+) R2 и R3 сводятся к новым целям сборки и платформенным доработкам (разрешение хоста в Firefox, Xcode-проект для Safari) — без изменений бэкенда и фич.
- (+) Одна форма и одни типы в трёх местах.
- (−) WXT пока на версиях 0.x (уточнить), возможны ломающие изменения. Версию фиксируем, обновляем отдельным PR.
- (−) Сессия `/survey` обрывается после 24 ч бездействия. Сотрудник, который отвечает через `/survey` (например, с телефона), будет входить по коду почти каждый рабочий день и всегда после выходных. Это расходится с ТЗ п. 4.4 и backlog F-005 (там 30 дней) и может снизить отклик (ADR-0008, Р-16). Расширения это не касается: у него бессрочный токен.
- (−) Пока нет поля «адрес сервера», расширение работает только с одним доменом.
