# ADR-0003. Браузерное расширение, API каналов ответа и аутентификация устройств

**Статус:** Принято
**Дата:** 2026-10-27
**Связано:** ТЗ п. 3.3, 3.4, 4.1, 4.3–4.7, 6.1–6.5, 6.7; CLAUDE.md «Расширение», «Персональные данные»; backlog F-001, F-004, F-005, F-010, F-031–F-039, F-078, F-079, Q-09, Q-10, Q-11, Q-32; решения заказчика В-06, В-07, В-08, В-09, В-14, отмена анонимности (ADR-0005)

## Контекст

- R1 — Chrome, Яндекс Браузер, Edge; R2 — Firefox; R3 — Safari. Один код (п. 3.1), Manifest V3, TypeScript.
- Разрешения: только `storage`, `alarms` и домен API. Ни вкладок, ни истории, ни контент-скриптов.
- Бейдж показывает число проектов с непройденным опросом. Статус проверяется при старте браузера, при открытии расширения, раз в 60 минут и после отправки ответа. Системных уведомлений нет.
- Форма опроса одна и та же в расширении, на `/survey` и в «Предпросмотре» кабинета (F-025, F-037, F-038).
- Вход только по коду из письма. Токен устройства бессрочный до отзыва, в БД хранится только его хэш.
- Анонимного комментария в форме нет. Комментарий всегда подписан (ADR-0005). Это сознательное отступление от ТЗ п. 6.5 по решению заказчика.
- On-premise в R1 не входит (В-07).

## Решение

### Фреймворк и структура

**WXT + Vue 3 + TypeScript.** WXT собирает из одного кода MV3 для Chromium, Firefox и Safari, даёт единое пространство `browser.*` и генерирует манифест под каждый браузер.

```
extension/
  wxt.config.ts            # манифест: permissions, host_permissions из env
  entrypoints/
    popup/                 # Vue-приложение (окно до 400×600)
    background.ts          # service worker: alarms, бейдж, проверка статуса
  src/
    api/                   # клиент /api/v1 (fetch, Bearer-токен, Accept-Language, ретраи); единственное место с базовым URL
    platform/              # тонкая обёртка над browser.*: badge, storage, alarms
    screens/               # экраны п. 6.3 + экран согласия
    stores/                # состояние (проекты, сессия, черновики)
  public/_locales/{ru,en}/messages.json   # имя и описание для магазинов
```

Общая форма опроса, типы контракта API и строки формы лежат в пакете `packages/survey-ui` (ADR-0006). Его используют расширение, `/survey` и предпросмотр.

### Сборки по браузерам

| Браузер | Команда | Артефакт | Релиз |
| --- | --- | --- | --- |
| Chrome | `wxt build -b chrome` | zip для Chrome Web Store | R1 |
| Яндекс Браузер | та же сборка Chrome | Устанавливается из Chrome Web Store (В-08, ТЗ п. 6.1) | R1 |
| Edge | `wxt build -b edge` | zip для Edge Add-ons (по содержимому совпадает с Chrome) | R1 |
| Firefox | `wxt build -b firefox --mv3` | xpi/zip для AMO, `browser_specific_settings.gecko.id` | R2 |
| Safari | `wxt build -b safari` → `safari-web-extension-converter` → Xcode | App Store | R3 |

Правила, которые делают R2 и R3 дешёвыми:
1. Код фич работает только через `browser.*` из WXT и `src/platform/`, без прямых вызовов `chrome.*`.
2. Используются лишь API, одинаково доступные во всех пяти браузерах: `storage.local`, `alarms`, `action.setBadgeText/BackgroundColor`, `runtime.onStartup/onInstalled/onMessage`.
3. Service worker не держит состояние в памяти: всё, что нужно между пробуждениями, лежит в `storage.local`.
4. Особенности, известные заранее. Firefox MV3 требует, чтобы пользователь явно выдал `host_permissions`, — в R2 нужен экран запроса разрешения на домен API. Safari — упаковка в приложение-контейнер и подпись через аккаунт Apple Developer заказчика (Q-09).

### Разрешения и домен API

- `permissions: ["storage", "alarms"]`, `host_permissions: ["https://<API_HOST>/*"]`. `API_HOST` берётся из переменной окружения сборки (`WXT_API_BASE_URL`); домен пока — заглушка (Q-09).
- Не запрашиваем `tabs`, `activeTab`, `notifications`, `scripting`, контент-скрипты и `storage.sync`.
- R1: один домен API, заданный при сборке (В-07).
- После R1: поле «адрес сервера» и `optional_host_permissions`.

### Аутентификация

| Канал | Механизм | Хранение и сроки |
| --- | --- | --- |
| Расширение (в будущем и мобильные приложения) | Токен Sanctum (`Authorization: Bearer`) | В БД `personal_access_tokens.token` = SHA-256, в браузере — `storage.local`. Бессрочный до отзыва (В-09) |
| `/survey`, кабинет, профиль | Cookie-сессия Sanctum (stateful, тот же домен), CSRF | Сессия в Redis, 14 дней (`SESSION_LIFETIME`, env; В-09) |

- Токен выдаётся на аккаунт и устройство. `name` — «браузер, ОС» (передаёт клиент). Тип клиента (`extension`, позже `mobile`, `telegram`) нужен HTTP-слою, чтобы проставить `channel` (ADR-0001). `last_used_at` обновляется не чаще заданного интервала.
- Выход в расширении удаляет текущий токен. Устройства отзываются на **общей странице профиля**. Она доступна любому аккаунту, в том числе сотруднику без доступа к кабинету (В-14); ссылки на неё есть в `/survey` и в настройках расширения.
- Исключение из проекта не трогает токен: доступ к проекту проверяет Policy по `memberships` на каждом запросе (п. 4.5.4). При удалении аккаунта все токены и сессии удаляются сразу.
- Коды входа: 6 цифр, хранятся как HMAC-SHA256 с ключом из env (простой SHA-256 от 6 цифр перебирается мгновенно). Код живёт 10 минут, на ввод 5 попыток, отправка не чаще раза в 60 секунд и не больше 10 писем в час на email. Счётчики лежат в БД и в Redis (RateLimiter). Тот же механизм с назначением `delete_project` подтверждает удаление проекта (В-09).
- **Согласие на ПДн (В-06).** Пока не принята текущая версия, middleware отвечает `consent_required` на все аутентифицированные эндпоинты, кроме профиля, согласия, выгрузки, удаления аккаунта, выхода и `GET /me/survey-status`. **Ответы не принимаются.** `survey-status` возвращает признак `consent_required`, чтобы расширение показало экран согласия.

### API каналов ответа (`/api/v1`, общий для расширения, `/survey` и будущего бота)

Ниже эскиз; финальные пути — в OpenAPI (`docs/openapi/openapi.yaml`).

| Метод и путь | Назначение | Аутентификация |
| --- | --- | --- |
| `POST /auth/codes` | Отправить код на email | нет, rate limit |
| `POST /auth/tokens` | Код → токен устройства (расширение) | нет, rate limit |
| `POST /auth/session` | Код → cookie-сессия (`/survey`) | нет, CSRF |
| `DELETE /auth/tokens/current`, `DELETE /auth/session` | Выход | да |
| `GET /me`, `PATCH /me` | Профиль: имя, язык, флаги `needs_profile`, `needs_consent` | да |
| `GET /consents/current`, `POST /me/consents` | Текст текущей версии согласия и его принятие | да |
| `GET /me/devices`, `DELETE /me/devices/{id}` | Устройства | да |
| `POST /invites/resolve` | Код приглашения → название проекта | нет, 10/мин с IP |
| `POST /join-requests`, `GET /me/join-requests` | Подать заявку, посмотреть статусы | да + согласие |
| `GET /me/survey-status` | Для бейджа и списка проектов: по каждому проекту — рабочий ли день, локальная дата, пройден ли опрос; общий флаг `consent_required` | да |
| `GET /projects/{project}/survey-days/today` | Опрос дня: вопросы с полным описанием и мой ответ, если он есть | да, участник + согласие |
| `PUT /projects/{project}/survey-days/today/response` | Создать или заменить ответ вместе с комментарием (идемпотентно, хранится последняя версия) | да, участник + согласие |

Выгрузка «мои данные» и удаление аккаунта — действия страницы профиля (Inertia, ADR-0001), не `/api/v1`.

Общие правила: JSON, локализация по `Accept-Language`, единый формат ошибок `{"error": {"code", "message", "fields"}}`, rate limiting на вход, коды, приглашения и опрос.

### Бейдж и надёжность формы

- Фоновый скрипт обновляет бейдж при `runtime.onStartup` и `onInstalled`, по `alarms.create('status', {periodInMinutes: 60})` и по сообщению от popup после отправки. Каждый раз он запрашивает `GET /me/survey-status` и вызывает `setBadgeText(n > 0 ? String(n) : '')`.
- Черновик хранится в `storage.local` под ключом `draft:<projectId>:<localDate>` и удаляется после успешной отправки или смены даты. При ошибке сети показываются сообщение и кнопка «Повторить»: `PUT` идемпотентен, поэтому повтор безопасен.
- Язык интерфейса берётся из `GET /me`, а до входа — из `browser.i18n.getUILanguage()` (ru, иначе en).

### CORS

В Chromium popup расширения с `host_permissions` ходит к API без CORS-проверок. Для Firefox, Safari и в качестве защиты ведётся allowlist происхождений расширений в `CORS_ALLOWED_ORIGINS` (env). Cookie расширение не использует.

## Рассмотренные альтернативы

1. **Plasmo** — завязан на React, а у нас Vue. Отклонено.
2. **Чистый Vite + webextension-polyfill + свои манифесты.** Пришлось бы вручную повторять то, что WXT уже делает. Отклонено.
3. **Ванильный TS без Vue в popup.** Форму опроса не получится переиспользовать. Отклонено.
4. **Cookie-сессия и для расширения.** Ненадёжно в Safari и Firefox, а ТЗ требует токены устройств. Отклонено.
5. **Поле «адрес сервера» уже в R1.** Отложено заказчиком (В-07).

## Последствия

- (+) R2 и R3 добавляют только цели сборки и платформенные доработки, без изменений бэкенда и фич.
- (+) Одна форма и одни типы для трёх мест.
- (+) Комментарий отправляется тем же `PUT` вместе с ответом, без отдельного эндпоинта.
- (−) WXT в версиях 0.x (уточнить): версию фиксируем, обновляем отдельным PR.
- (−) Пока нет поля «адрес сервера», расширение работает только с одним доменом.
- (−) Сессия `/survey` — 14 дней вместо 30 по ТЗ п. 4.4. Это решение заказчика, backlog F-005 обновлён.
