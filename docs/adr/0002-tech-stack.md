# ADR-0002. Технологический стек и версии

**Статус:** Принято
**Дата:** 2026-10-27
**Связано:** ТЗ п. 3.1, 3.4, 3.5, 7.6, 9.3, 9.4, 9.6; CLAUDE.md «Стек», «Очереди»; backlog Q-05, Q-07, Q-24, F-064–F-071; решения заказчика В-09, В-10

## Контекст

Обязательная часть стека задана ТЗ и CLAUDE.md: PHP + Laravel, PostgreSQL 16+, Redis + Queue + Horizon, Scheduler, Sanctum, Inertia + Vue (Q-05), Docker Compose, Nginx + PHP-FPM. Остаётся выбрать конкретные версии и вспомогательные библиотеки. Правило: новая зависимость добавляется только с обоснованием.

Номера версий ниже — по состоянию знаний на дату ADR. Где я не уверен, что ветка уже вышла или стабильна, стоит «уточнить»: при инициализации проекта нужно зафиксировать фактическую последнюю стабильную версию и записать её в этот ADR.

## Решение

### Backend

| Компонент | Версия | Зачем |
| --- | --- | --- |
| PHP (FPM, CLI) | 8.5.x | Актуальная стабильная ветка (вышла в ноябре 2025). Если к старту выйдет 8.6/9.0 — не брать до первого патч-релиза |
| Laravel | 13.x — **уточнить**; запасной вариант 12.x | Последняя мажорная ветка. Если 13.x на старте ещё нет или пакеты экосистемы (Horizon, Sanctum, Larastan) её не поддерживают — 12.x |
| Laravel Sanctum | 4.x — уточнить | Токены устройств (SHA-256 в БД) и cookie-сессии в одном guard |
| Laravel Horizon | 5.x — уточнить | Обязателен по ТЗ, супервизоры по очередям |
| Composer | 2.x | — |
| PHPUnit | версия, идущая с Laravel | Тесты. Pest не добавляем: лишняя зависимость без выигрыша для пилота |
| Larastan / PHPStan | 3.x / 2.x — уточнить | Уровень ≥ 6 (стартуем с 6, цель — 8) |
| Laravel Pint | идущая с Laravel | Стиль |

В R1 не добавляем:
- `laravel/telescope` — пишет тела запросов, что конфликтует с анонимностью;
- Reverb/WebSocket (см. ниже);
- пакеты модульности (ADR-0001);
- Pennant — флаги функций реализуем своей таблицей (ADR-0004).

### Данные и инфраструктура

| Компонент | Версия | Зачем |
| --- | --- | --- |
| PostgreSQL | 18.x (минимум 16 по ТЗ) | Стабильная ветка с 2025 г. Используем `timestamptz`, `date`, `jsonb`, частичные уникальные индексы, `citext` для email |
| Redis | 8.x — уточнить минор (решение В-10) | Очереди, кеш, rate limiting, сессии |
| Nginx | актуальная stable-ветка (1.28+ — уточнить) | Статика, прокси в PHP-FPM, политика логов (ADR-0005) |
| Mailpit | 1.x | Только локально: перехват писем |

Конфигурация Redis: одна инстанция, разные логические БД для `queue`, `cache` и `session`; `maxmemory-policy noeviction` (вытеснение не должно съесть задачи); AOF включён — это нужно и для очередей, и для счётчика «один анонимный комментарий в день» (ADR-0005). Драйвер очереди задаётся через `QUEUE_CONNECTION`, бизнес-код о Redis не знает (п. 3.5.5).

Лицензия Redis 8 (RSALv2/SSPL/AGPLv3) для пилота у заказчика препятствием не является. При будущей поставке клиентам её нужно проверить: это зафиксировано как риск (ADR-0008, Р-10), продукт не меняем.

### Сессии и токены (В-09)

- Cookie-сессия кабинета и `/survey` завершается после **24 часов бездействия** (`SESSION_IDLE_TIMEOUT` — стандартный скользящий `SESSION_LIFETIME` Laravel). Абсолютный срок — **14 дней** с момента входа (`SESSION_ABSOLUTE_LIFETIME`). Его проверяет небольшой middleware в Identity по метке входа, сохранённой в сессии: из коробки Laravel умеет только скользящий срок. Оба значения задаются в env.
- Токены устройств бессрочные до отзыва.

### Очереди и периодические задачи

- Очереди: `mail` (отдельный супервизор Horizon, всегда ≥ 1 процесс), `analytics`, `ai` (в R1 сконфигурирована, задач нет), `default`.
- Все задачи: `tries` + экспоненциальный `backoff`, идемпотентность по естественному ключу (`project_id + local_date` и т. п.); `failed()` записывает окончательный сбой в лог и в отчёт об ошибках.
- Scheduler (`schedule:work` в отдельном контейнере):
  - каждую минуту — открытие и закрытие дней опроса по часовым поясам проектов;
  - ночью — полный пересчёт агрегатов;
  - периодически — очистка кодов, заявок, экспортов и записей журнала старше года.

  Физического удаления мягко удалённых данных в Scheduler нет: по решению В-05 оно выполняется вручную.
- Horizon доступен только системному администратору: gate по списку email из `HORIZON_ADMIN_EMAILS` (это не роль проекта).

### Обновление интерфейса без перезагрузки

Экспорт (R1) и AI-сводка (R2): **polling** статуса раз в 2–3 секунды, пока задача не завершена. Новые зависимости и отдельный WebSocket-сервер не нужны. Перейти на Reverb можно позже без изменения модулей: событие завершения уже есть. Предлагается как ответ на Q-24.

### PDF (R2)

В R1 движок не выбираем. Ограничение: генерация идёт в очереди, а графики для PDF строятся на сервере. Варианты для R2: headless Chromium (Browsershot/Gotenberg) или серверный рендер ECharts в SVG + dompdf. Решение — отдельным ADR в R2.

### Мониторинг и отчёт об ошибках

В R1 — только абстракция: стандартный канал логов Laravel и драйвер отчёта об ошибках через env (по умолчанию `log`). Sentry или self-hosted аналог (GlitchTip) выбираем вместе с хостингом (Q-07). Обязательное требование к любому драйверу: не отправлять тела запросов и IP (ADR-0005).

## Рассмотренные альтернативы

1. **Livewire вместо Inertia.** Закрыто решением Q-05.
2. **Chart.js вместо ECharts.** Легче, но тепловая карта и аннотации требуют по плагину. Отклонено.
3. **WebSocket (Reverb) для статусов.** Лучше UX, но это новый долгоживущий процесс, а задачи редкие. Отклонено для R1.
4. **Совместимый форк Redis с более свободной лицензией.** Рассматривался из-за лицензии Redis 8. Заказчик выбрал Redis (В-10): поставки клиентам в R1 нет.
5. **RabbitMQ как брокер.** По ТЗ отдельный брокер в пилоте не нужен. Код от драйвера не зависит, но Horizon работает только с Redis (ADR-0008).

## Последствия

- (+) Минимум новых зависимостей: всё, кроме ECharts, vue-i18n и Tailwind, приходит с Laravel или Inertia. Каждая добавленная зависимость обоснована выше.
- (+) Одна инстанция Redis и один PHP-образ для app, horizon и scheduler; стек официально поддерживается Laravel и Horizon.
- (−) Перед поставкой клиентам нужна проверка лицензии Redis 8 (Р-10).
- (−) Абсолютный срок сессии — свой middleware, его нужно покрыть тестами.
- (−) Версии с пометкой «уточнить» нужно зафиксировать в `composer.json`, `package.json`, `compose.yaml` при инициализации и обновить этот ADR.
