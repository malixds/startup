# ADR-0002. Технологический стек и версии

**Статус:** Принято
**Дата:** 2026-10-27
**Связано:** ТЗ п. 3.1, 3.4, 3.5, 7.6, 9.3, 9.4, 9.6; CLAUDE.md «Стек», «Очереди»; backlog Q-05, Q-07, Q-24, F-005, F-064–F-071; решения заказчика В-09, В-10

## Контекст

Обязательная часть стека задана ТЗ и CLAUDE.md: PHP + Laravel, PostgreSQL 16+, Redis + Queue + Horizon, Scheduler, Sanctum, Inertia + Vue (Q-05), Docker Compose, Nginx + PHP-FPM. Остаётся выбрать конкретные версии и вспомогательные библиотеки. Новая зависимость добавляется только с обоснованием.

Версии указаны по состоянию знаний на дату ADR. Где нет уверенности, что ветка уже вышла или стабильна, стоит пометка «уточнить». При инициализации проекта фактические последние стабильные версии фиксируются и вносятся в этот ADR.

## Решение

### Backend

| Компонент | Версия | Зачем |
| --- | --- | --- |
| PHP (FPM, CLI) | 8.5.x | Актуальная стабильная ветка (вышла в ноябре 2025). Если на старте выйдет 8.6/9.0 — не брать до первого патч-релиза |
| Laravel | 13.x — **уточнить**; запасной вариант 12.x | Последняя мажорная ветка. Если 13.x ещё нет или Horizon, Sanctum и Larastan её не поддерживают — 12.x |
| Laravel Sanctum | 4.x — уточнить | Токены устройств (SHA-256 в БД) и cookie-сессии в одном guard |
| Laravel Horizon | 5.x — уточнить | Обязателен по ТЗ, супервизоры по очередям |
| Composer | 2.x | — |
| PHPUnit | версия, идущая с Laravel | Тесты. Pest не добавляем: лишняя зависимость без выигрыша для пилота |
| Larastan / PHPStan | 3.x / 2.x — уточнить | Уровень ≥ 6 (стартуем с 6, цель — 8) |
| Laravel Pint | идущая с Laravel | Стиль |

Что не ставим в R1:
- `laravel/telescope` — пишет тела запросов с ПДн (ответы, комментарии).
- Reverb/WebSocket — см. ниже.
- Пакеты модульности — ADR-0001.
- Pennant — флаги функций делаем своей таблицей, ADR-0004.

### Данные и инфраструктура

| Компонент | Версия | Зачем |
| --- | --- | --- |
| PostgreSQL | 18.x (минимум 16 по ТЗ) | Стабильная ветка с 2025 г. Используем `timestamptz`, `date`, `jsonb`, частичные уникальные индексы, `citext` для email |
| Redis | 8.x — уточнить минор (В-10) | Очереди, кеш, rate limiting, сессии |
| Nginx | актуальная stable-ветка (1.28+ — уточнить) | Статика, прокси в PHP-FPM, ротация логов |
| Mailpit | 1.x | Только локально: перехват писем |

Конфигурация Redis: одна инстанция; разные логические БД для `queue`, `cache` и `session`; `maxmemory-policy noeviction`, чтобы вытеснение не удаляло задачи; AOF включён, чтобы задачи переживали перезапуск. Драйвер очереди задаётся через `QUEUE_CONNECTION`, бизнес-код о Redis не знает (п. 3.5.5).

Лицензия Redis 8 (RSALv2/SSPL/AGPLv3) пилоту у заказчика не мешает. При будущей поставке клиентам её нужно проверить. Это записано как риск (ADR-0008, Р-10), продукт не меняем.

### Сессии и токены (В-09)

- Cookie-сессия кабинета и `/survey` живёт **14 дней**: стандартный `SESSION_LIFETIME` Laravel = 20160 минут, значение задаётся в env. Своих middleware для сроков сессии нет. В Laravel этот срок отсчитывается от последнего запроса (уточнение — В-20).
- Токены устройств бессрочные, пока их не отзовут.

### Очереди и периодические задачи

- Очереди: `mail` (отдельный супервизор Horizon, всегда не меньше одного процесса), `analytics`, `ai` (в R1 настроена, задач нет), `default`.
- У всех задач — `tries` и экспоненциальный `backoff`, идемпотентность по естественному ключу (`project_id + local_date` и т. п.). `failed()` записывает окончательный сбой в лог и в отчёт об ошибках.
- Удаление аккаунта, проекта и ответов исключённого участника выполняется синхронно, в одной транзакции (ADR-0001). Пересчёт агрегатов после удаления ставится в очередь `analytics`.
- Scheduler (`schedule:work` в отдельном контейнере):
  - каждую минуту — открытие и закрытие дней опроса по часовым поясам проектов;
  - ночью — полный пересчёт агрегатов;
  - периодически — очистка просроченных кодов, заявок, экспортов и записей журнала старше года.
- Horizon доступен только системному администратору: gate по списку email из `HORIZON_ADMIN_EMAILS` (это не роль проекта).

### Обновление интерфейса без перезагрузки

Статус экспорта (R1) и AI-сводки (R2) клиент опрашивает (**polling**) раз в 2–3 секунды, пока задача не завершится. Не нужны ни новые зависимости, ни отдельный WebSocket-сервер. Перейти на Reverb можно позже, не меняя модули: событие завершения уже есть. Это предлагаемый ответ на Q-24.

### PDF (R2)

В R1 движок не выбираем. Ограничения: генерация идёт в очереди, графики для PDF строятся на сервере. Варианты для R2: headless Chromium (Browsershot или Gotenberg) либо серверный рендер ECharts в SVG + dompdf. Решение — отдельным ADR в R2.

### Мониторинг и отчёт об ошибках

В R1 — только абстракция: стандартный канал логов Laravel и драйвер отчёта об ошибках через env (по умолчанию `log`). Sentry или self-hosted аналог (GlitchTip) выбираем вместе с хостингом (Q-07). Требование к любому драйверу: не отправлять тела запросов и IP (ADR-0005).

## Рассмотренные альтернативы

1. **Livewire вместо Inertia.** Закрыто решением Q-05.
2. **Chart.js вместо ECharts.** Легче, но для тепловой карты и аннотаций нужно по плагину. Отклонено.
3. **WebSocket (Reverb) для статусов.** UX лучше, но это новый долгоживущий процесс, а задачи редкие. Отклонено для R1.
4. **Совместимый форк Redis с более свободной лицензией.** Заказчик выбрал Redis (В-10): поставки клиентам в R1 нет.
5. **RabbitMQ как брокер.** По ТЗ отдельный брокер в пилоте не нужен. Код от драйвера не зависит, но Horizon работает только с Redis (ADR-0008).
6. **Выход после 24 часов бездействия плюс абсолютный срок 14 дней.** Был в предыдущей редакции. Отменён заказчиком: просто 14 дней.

## Последствия

- (+) Минимум новых зависимостей: всё, кроме ECharts, vue-i18n и Tailwind, приходит вместе с Laravel или Inertia. Каждая добавленная зависимость обоснована выше.
- (+) Одна инстанция Redis и один PHP-образ для app, horizon и scheduler. Связку официально поддерживают Laravel и Horizon.
- (+) Сроки сессии — стандартный механизм Laravel, своего кода нет.
- (−) Перед поставкой клиентам нужна проверка лицензии Redis 8 (Р-10).
- (−) Версии с пометкой «уточнить» нужно зафиксировать в `composer.json`, `package.json` и `compose.yaml` при инициализации и обновить этот ADR.
