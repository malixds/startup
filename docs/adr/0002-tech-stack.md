# ADR-0002. Технологический стек и версии

**Статус:** Принято
**Дата:** 2026-10-27
**Связано:** ТЗ п. 3.1, 3.4, 3.5, 7.6, 9.3, 9.4, 9.6; CLAUDE.md «Стек», «Очереди»; backlog Q-05, Q-07, Q-24, F-005, F-064–F-071; решения заказчика В-09, В-10, В-20, В-21

## Контекст

Обязательную часть стека задают ТЗ и CLAUDE.md: PHP + Laravel, PostgreSQL 16+, Redis + Queue + Horizon, Scheduler, Sanctum, Inertia + Vue (Q-05), Docker Compose, Nginx + PHP-FPM. Остаётся выбрать версии и вспомогательные библиотеки. Новая зависимость добавляется только с обоснованием.

Версии указаны по состоянию знаний на дату ADR. «Уточнить» стоит там, где нет уверенности, что ветка уже вышла или стабильна. При инициализации проекта фактические версии нужно зафиксировать в этом ADR.

## Решение

### Backend

| Компонент | Версия | Зачем |
| --- | --- | --- |
| PHP (FPM, CLI) | 8.5.x | Актуальная стабильная ветка (ноябрь 2025) |
| Laravel | 13.x — **уточнить**; запасной вариант 12.x | Последняя мажорная ветка. Если 13.x нет или её не поддерживают Horizon, Sanctum и Larastan — берём 12.x |
| Laravel Sanctum | 4.x — уточнить | Токены устройств и cookie-сессии в одном guard |
| Laravel Horizon | 5.x — уточнить | Обязателен по ТЗ |
| Composer | 2.x | — |
| PHPUnit | идущая с Laravel | Тесты. Pest не добавляем |
| Larastan / PHPStan | 3.x / 2.x — уточнить | Уровень ≥ 6 |
| Laravel Pint | идущая с Laravel | Стиль |

Не ставим в R1:
- `laravel/telescope` — пишет тела запросов с ПДн;
- Reverb;
- пакеты модульности;
- Pennant.

### Данные и инфраструктура

| Компонент | Версия | Зачем |
| --- | --- | --- |
| PostgreSQL | 18.x (минимум 16 по ТЗ) | `timestamptz`, `date`, `jsonb`, частичные уникальные индексы, `citext` |
| Redis | 8.x — уточнить минор (В-10) | Очереди, кеш, rate limiting, сессии |
| Nginx | stable-ветка (1.28+ — уточнить) | Статика, прокси в PHP-FPM, ротация логов |
| Mailpit | 1.x | Только локально |

Redis работает одной инстанцией с отдельными логическими БД для `queue`, `cache` и `session`. Настройки: `noeviction`, AOF. Драйвер очереди задаётся через `QUEUE_CONNECTION`.

Лицензию Redis 8 нужно проверить перед будущей поставкой клиентам (ADR-0008, Р-10); продукт ради этого не меняем.

### Сессии и токены (В-09, В-20)

- Cookie-сессия кабинета и `/survey` живёт **14 дней с последнего запроса** — стандартный скользящий `SESSION_LIFETIME` Laravel = 20160 минут, задаётся в env. Своих middleware для сроков нет. Активный пользователь не выходит, пока пользуется системой (В-20).
- Токены устройств бессрочные до отзыва.

### Очереди и периодические задачи

- Очереди: `mail` (отдельный супервизор), `analytics`, `ai` (в R1 задач нет), `default`.
- Все задачи используют `tries` и экспоненциальный `backoff`, идемпотентны, окончательный сбой логируется в `failed()`.
- Удаление аккаунта, проекта и ответов исключённого участника выполняется синхронно в одной транзакции (ADR-0001), пересчёт агрегатов после него — в очереди `analytics`.
- Scheduler (`schedule:work`):
  - каждую минуту — открытие и закрытие дней опроса;
  - ночью — полный пересчёт агрегатов;
  - периодически — очистка просроченных кодов, заявок, экспортов, записей `audit_log` старше года и **записей `deletion_log` старше года** (В-21).
- Horizon доступен только системному администратору (`HORIZON_ADMIN_EMAILS`).

### Обновление без перезагрузки

Статус экспорта (R1) и сводки (R2) клиент опрашивает каждые 2–3 секунды. Новых зависимостей для этого не нужно. Это предлагаемый ответ на Q-24.

### PDF (R2)

Движок выбираем отдельным ADR в R2. Генерация идёт в очереди, графики строятся на сервере.

### Мониторинг

В R1 — абстракция (`ERROR_REPORTER`, по умолчанию `log`); Sentry или GlitchTip выбираем вместе с хостингом. Драйвер не должен отправлять тела запросов и IP.

## Рассмотренные альтернативы

1. **Livewire.** Закрыто решением Q-05.
2. **Chart.js.** Для нужных графиков понадобились бы плагины. Отклонено.
3. **Reverb.** Лишний процесс. Отклонено для R1.
4. **Форк Redis с другой лицензией.** Заказчик выбрал Redis (В-10).
5. **RabbitMQ.** По ТЗ не нужен.
6. **Выход по бездействию 24 ч / абсолютный срок сессии от входа.** Отменено заказчиком (В-09, В-20).

## Последствия

- (+) Минимум новых зависимостей, каждая обоснована.
- (+) Сроки сессии задаются стандартным механизмом Laravel.
- (−) Сессия у активного пользователя фактически бессрочна (Р-24).
- (−) Перед поставкой клиентам нужна проверка лицензии Redis 8 (Р-10).
- (−) Версии с пометкой «уточнить» нужно зафиксировать при инициализации.
