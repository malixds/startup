# ADR-0008. Риски, технический долг релиза 1 и порядок реализации

**Статус:** Принято
**Дата:** 2026-10-27
**Связано:** ADR-0001–0007; backlog раздел 4 (зависимости), раздел 5 (G-01–G-30), раздел 6 (Q-10–Q-32); решения заказчика В-01–В-23; `docs/legal-questions.md`; мелкие решения — `docs/decisions.md`

## Контекст

R1 — рабочий пилот на Chromium и `/survey`. Дизайна, текстов ПДн, домена и хостинга пока нет. On-premise в R1 не входит (В-07). Анонимности нет (ADR-0005). ПДн удаляются физически и сразу, вместе со связанными записями журнала (В-05, В-19). Факт удаления записывается в `deletion_log`, его видит только системный администратор (В-21, В-23). В документе перечислено, на что мы сознательно идём и в каком порядке строим.

## Решение

### Сознательный технический долг R1

| Долг | Почему приемлемо | Когда вернуть |
| --- | --- | --- |
| Кабинет на Inertia без REST (В-01) | Сервисы канал-независимы | При мобильном приложении кабинета |
| Изоляция проектов без RLS | Policy + scope + тесты | При многоарендной продаже |
| Polling вместо WebSocket | Задачи редкие | С realtime-алертами |
| Флаги функций без UI | Один флаг | С тарифами |
| Календарь только по дням недели | F-027 отложен | С F-027 |
| Внешние метрики — только контракт | Трекеры не в пилоте | С интеграциями |
| Реестр удалений без UI, только artisan (решение В-23) | Нужен для проверок, а не для повседневной работы | По запросу заказчика |
| Типы API на клиенте вручную | API небольшой | При расхождениях |
| Экспорты на локальном диске | Один сервер | При нескольких узлах |
| Нет e2e-тестов расширения | Ручной чек-лист | После стабилизации |
| Расширение с одним доменом | On-premise вне R1 | Перед установкой у клиента |
| Заглушки текстов | Q-08 | По мере поставки |
| Нет prod-compose, бэкапов, мониторинга | Q-07 | При выборе хостинга |

### Порядок реализации R1

Каждый шаг — законченный PR с тестами и обновлённым OpenAPI. Новые типы фиксируются в `docs/new_types.md` (В-12), мелкие решения — в `docs/decisions.md`.

1. **Фундамент.** Монорепо, compose (Redis 8), Laravel, каркас модулей, Horizon, Scheduler, CI, `/health`. (F-064, F-065, F-067, F-069, F-070, F-071)
2. **Identity + Notifications.** Вход, письма, сессии, токены, профиль, согласие. (F-001–F-005, F-068)
3. **Projects + Audit.** Проект, роли, Policies, код приглашения, заявки, флаг участия (`MemberParticipationChanged`), передача владения, исключение, удаление проекта (физически, вместе с журналом, запись в `deletion_log`), флаги, журнал, реестр удалений (artisan-команда чтения, очистка через Scheduler). (F-007–F-011, F-013–F-018, F-059, F-061, F-077)
4. **Survey.** (F-019–F-026, F-028, F-029)
5. **Responses + общий пакет формы.** (F-031–F-033, F-037, F-038, F-062)
6. **Расширение Chromium.** (F-034–F-036, F-039)
7. **Analytics.** Снимок ожидаемых при открытии дня, уменьшение снимка в течение дня (В-22), `ParticipationCalculator`, индекс, дашборд, CSV. (F-040–F-049, F-051)
8. **Права субъекта и завершение.** Выгрузка; физическое удаление аккаунта с записью в `deletion_log` и тестами полноты (Р-22, Р-26); сидер; замеры; документация. (F-006, F-072, F-073, F-074)

## Рассмотренные альтернативы

1. **Ждать ответов на все вопросы.** Отклонено. Мелкие решения принимаются сами и фиксируются в `docs/decisions.md`.
2. **Сразу закрыть долг.** Отклонено.

## Последствия

- Долг пересматривается при планировании R2.
- Ответы на ЮВ-2, ЮВ-3, ЮВ-4 и вопросы из индекса меняют сервисы, а не схему.
